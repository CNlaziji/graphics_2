## 📋 项目简介与技术架构

### 核心架构

本项目实现了基于 **双通路渲染（Dual-Pass Rendering）** 的实时阴影映射系统：

```
┌─────────────────────────────────────────────────────────────┐
│                    第一通路：Shadow Pass                      │
│  从光源视角渲染深度图 → 生成 Shadow Map（深度纹理）            │
└─────────────────────────────────────────────────────────────┘
                              ↓
┌─────────────────────────────────────────────────────────────┐
│                   第二通路：Lighting Pass                     │
│  主场景渲染 + 光照计算 + 阴影检测（PCF采样）                   │
└─────────────────────────────────────────────────────────────┘
```

### 技术规范

| 技术项 | 规格 | 说明 |
|--------|------|------|
| **语言标准** | C++17 | 现代C++特性，如 `std::unique_ptr`, `constexpr` |
| **OpenGL版本** | 3.3 Core Profile | 核心模式，废弃固定管线 |
| **窗口系统** | GLFW 3.4 | 跨平台窗口与输入管理 |
| **函数加载** | GLAD | OpenGL函数指针加载器 |
| **数学库** | GLM 1.0.1 | 向量、矩阵运算与变换 |
| **构建系统** | CMake 3.15+ | 一键编译，跨平台支持 |

> ⚠️ **禁止使用的技术**: Unity, Unreal Engine, Godot 等商业游戏引擎

### ⚠️⚠️⚠️ 核心警告：工作目录配置 ⚠️⚠️⚠️

**必须将 IDE 的【工作目录 (Working Directory)】设置为项目根目录！**

#### 为什么？

代码中使用的是**相对路径**：
```cpp
// 着色器路径
const char* vertexShaderPath = "shaders/scene.vert";

// 模型路径
const char* modelPath = "models/building.obj";

// 纹理路径
const char* texturePath = "textures/wood.png";
```

如果工作目录配置错误，程序会因找不到文件而**直接崩溃**。

#### 各 IDE 配置方法

| IDE | 配置路径 |
|-----|----------|
| **Visual Studio** | 项目属性 → 调试 → 工作目录 → 设置为 `$(ProjectDir)..\` |
| **CLion** | Run → Edit Configurations → Working directory → 选择项目根目录 |
| **Trae/VS Code** | `.vscode/launch.json` 中设置 `"cwd": "${workspaceFolder}"` |

> 🔴 **验证方法**: 运行程序前，确保可执行文件所在目录包含 `shaders/` 和 `models/` 文件夹（或能正确指向项目根目录的这些文件夹）。

## ❓ 常见问题 (FAQ)

**Q: 编译时出现 "找不到 glfw3" 错误？**  
A: 确保 `lib/` 目录下有 `libglfw3.a` (MinGW) 或 `glfw3.lib` (MSVC) 文件。

**Q: 运行时报错 "找不到 shaders/scene.vert"？**  
A: **工作目录配置错误！** 请检查 IDE 的 Working Directory 是否设置为项目根目录。

**Q: 如何添加新的源文件？**  
A: 修改 `CMakeLists.txt` 中的 `SOURCE_FILES` 列表，然后重新运行 `cmake -B build`。

**Q: 可以修改 ShadowPipeline.hpp 吗？**  
A: 建议先与组长沟通。核心渲染管线由组长维护，组员主要扩展 `RenderScene()` 等内容。
